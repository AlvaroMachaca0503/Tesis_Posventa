# R7.7 — Siguiente versión del prototipo (pista P)

**Estado:** BORRADOR · **Versión:** 0.1 · **Fecha:** 17/10/2026 · **Fuente única:** «Pendiente para R7.7 (pedido del investigador, 17/10/2026)» en `docs/historial/R7/CLAUDE_RMotriz_tesis_contexto.md`. Esta spec **no añade pedidos**: los ordena y deja explícitas las preguntas.
**Pista P:** prototipo HTML local de demostración. No es la implementación real (pista S).

## 1. Cómo se construye una versión
Según `CLAUDE_RMotriz_tesis_contexto.md` («Cómo trabajar el prototipo»): arquitectura **por capas** (cada versión agrega una capa al final del `<script>`, redefine funciones con `const base = fn; fn = function(){…}` y el CSS se inserta antes de `</style></head>`).
1. Crear **prototipo/capas/r77/** y **prototipo/capas/aplicar_r77.py** (a crear; todavía no existen) (copiar `aplicar_r76.py`: cambian el directorio, la lista de archivos y las cadenas de versión).
2. Reconstruir con la cadena `aplicar_r72 … aplicar_r77` (**con `python`, no `python3`; en Windows se normalizan los saltos de línea**: ver `docs/plan/ENTORNO.md` §3).
3. Revisar la sintaxis (`node --check` del último `<script>`).
4. Pruebas Playwright: `base.mjs` (todas las vistas sin errores) y un `e2e77.mjs` nuevo; **mantener la regresión** de `e2e76`, `e2e75`, `e2e74_sobre_r76`, `e2e73_sobre_r74`, `e2e_regresion72`.
5. Escribir `CAMBIOS_R7.7.md` (qué cambió, decisiones a confirmar, pruebas) en `docs/historial/R7/`.
6. El estado vive en `db`; las claves `db.r74*`, `db.r75*` y `db.r76*` se migran al abrir (`r7XEnsure`). Clave de almacenamiento: `rmotriz-modulos-r7-1-v1`.

**Reglas obligatorias:** solo datos sintéticos; no es producción; marcar decisiones y conflictos; no afirmar sin probar; reglas del profesor para UML y LaTeX (`AGENTS.md`).
