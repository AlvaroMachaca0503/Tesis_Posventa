# R7.7 — Cómo se crearían las 3 reglas iniciales con el nuevo motor

**Estado:** BORRADOR para validar · **Fecha:** 17/10/2026 · **No se implementó nada.** Describe cómo quedarían las tres reglas que hoy están **fijas en el código** (`prototipo/capas/r74/e_auto.js`) cuando sean **datos configurables** del motor «Cuando / Y si / Entonces» (`R7.7-motor-automatizaciones.md`, `docs/plan/ANALISIS_AUTOMATIZACION_Y_TAREAS_R77.md`).
**Cómo se obtuvo:** leyendo `e_auto.js` completo (`r74KmScan`, `r74CitaScan`, `r74PostScan`, `r74RunAuto`) y `r74KmConsult`. Cada comportamiento descrito aquí **existe hoy**, salvo lo marcado **(nuevo)**. **No se ejecutó** el prototipo.
**Objetivo:** al migrar, el motor debe producir **las mismas tareas que hoy** (prueba de regresión, sección 6).

## 0. Cómo se describe una regla (la «ficha»)
| Campo | Qué es |
|---|---|
| **Nombre** | Texto libre |
| **Cuando** | Qué la dispara y sus parámetros. Hay **tres tipos de disparador**: **evento** (algo ocurre), **tiempo relativo** (pasa un plazo desde una fecha de un registro) y **estado calculado** (una condición que el sistema calcula) |
| **Y si** | Condiciones extra (0 a 3). Se pueden añadir sin tocar el código |
| **Entonces** | Hasta 3 acciones. Aquí, una: **crear tarea** con una **plantilla** que usa variables `{…}` |
| **Clave anti-duplicado** | Qué hace que «ya se creó esta tarea» (evita repetir en cada revisión) |
| **Se cierra cuando** | Qué completa la tarea automáticamente |
| **Botones de la tarea** | Accesos rápidos que trae la plantilla |
| **Responsable y lista** | A quién y dónde se crea (editable; hoy el valor por defecto es la cajera y la lista Posventa) |
| **Activa** | Interruptor |

Las 3 reglas iniciales **no** son de tipo «evento»: la de km es **estado calculado**; la de cita y la de posventa son **tiempo relativo**. El motor debe soportar los tres tipos desde la Fase 1.

## 1. Regla 1 — Consultar km antes del cambio de aceite
**En una frase:** *Cuando a un vehículo le falten ≤ 500 km **o** ≤ 7 días para el cambio de aceite (o ya esté vencido), crear una tarea para llamar al cliente y preguntarle el kilometraje.*

### 1.1 Ficha
| Campo | Valor |
|---|---|
| **Cuando** | **Estado calculado** «proximidad del cambio de aceite». Se cumple si el cambio de aceite **está vencido**, **o** faltan ≤ **[500]** km, **o** faltan ≤ **[7]** días. Lo que ocurra primero. El cálculo usa la línea temporal (último km conocido de una ODS o consulta y tasa km/mes) |
| **Y si** (de fábrica) | El vehículo **tiene plan asignado** y la línea temporal tiene una regla de aceite · **no existe** ya una tarea de km abierta de ese vehículo |
| **Y si** (el usuario puede añadir) | Sede = … · Marca = … *(nuevo)* |
| **Entonces** | **Crear tarea** (ver 1.3) |
| **Clave anti-duplicado** | `km-{vehículo}-{km del próximo cambio}`: **una sola tarea por ciclo de cambio de aceite** (después de registrar la consulta no se vuelve a crear para el mismo ciclo) |
| **Se cierra cuando** | Se **registra una consulta de km** de ese vehículo (completa las tareas de km abiertas de ese vehículo) |
| **Botones de la tarea** | «⏱ Registrar consulta de km» · «↗ Ver línea temporal» |
| **Responsable / lista** | Editables (hoy por defecto: cajera / Posventa) |

### 1.2 Pantalla (esquema)
```
Regla: Consultar km antes del cambio de aceite                    [● Activa]
 CUANDO   [Estado calculado ▾] Cambio de aceite próximo o vencido
          Faltan ≤ [ 500 ] km  o  ≤ [ 7 ] días  (lo que ocurra primero)
 Y SI     [vehículo con plan]  [sin tarea de km abierta]   [+ condición]
 ENTONCES [Crear tarea ▾]
          Lista [Posventa ▾]  Responsable [Cajera ▾]  Vence [hoy ▾]
          Prioridad [Alta si está vencido, si no Normal]
          Título   Consultar km · {placa} ({motivo})
          Detalle  (plantilla abajo)                         [Probar] [Guardar]
```

### 1.3 Plantilla de la tarea
| Campo | Valor |
|---|---|
| Tipo / estado | Tarea · Pendiente |
| **Título** | `Consultar km · {placa} ({motivo})` donde `{motivo}` = «cambio de aceite vencido» · «faltan N km» · «faltan N días» |
| **Prioridad** | **Alta** si el cambio está vencido; **Normal** si no |
| Inicio / vence | **hoy** (fecha del sistema o simulada); hora de inicio = ahora; hora límite 18:00 |
| Etiquetas | `Automatización`, `Consulta km` |
| Creada por | «Sistema» |
| **Detalle** | *Llamar a {cliente} ({teléfono si existe}) y preguntar el kilometraje actual de {placa}. Registrar la respuesta con «Registrar consulta de km»: la línea temporal se recalcula. No se agenda cita automáticamente. Km estimado hoy: {km_estimado} · próximo cambio de aceite: {km_proximo} km ({fecha_proximo}). Servicios: {lista de servicios con su estado: Vencido / Por vencer / Próximo}* |
| Datos que guarda la tarea | vehículo, km estimado, km del cambio, km faltantes, días, lista de servicios (para el panel) |

### 1.4 Cómo se crearía paso a paso (en pantalla)
1. **Automatizaciones → + Nueva regla → Plantillas → «Consultar km»** (o «Desde cero»).
2. En **Cuando**, elegir **Estado calculado → Cambio de aceite próximo o vencido** y poner **500** km y **7** días.
3. En **Y si**, dejar las dos condiciones de fábrica; opcionalmente **+ condición** (sede).
4. En **Entonces → Crear tarea**, elegir **lista** y **responsable**, y revisar título y detalle (las variables se insertan con un selector).
5. **Probar** (muestra qué vehículos cumplirían hoy y qué tareas se crearían, **sin crearlas**) → **Guardar** → activar.

### 1.5 Pruebas de regresión
- Vehículo con plan, a ≤ 500 km del cambio → **1** tarea «Consultar km · PLACA (faltan N km)» con prioridad Normal.
- Mismo vehículo, cambio vencido → prioridad **Alta** y motivo «cambio de aceite vencido».
- Segunda pasada sin cambios → **0** tareas nuevas (clave anti-duplicado).
- Con una tarea de km abierta de ese vehículo → **0** tareas nuevas.
- Registrar la consulta de km → la tarea queda **Completada** y la línea temporal se recalcula.
- Vehículo sin plan → **0** tareas.

## 2. Regla 2 — Confirmar cita
**En una frase:** *Cuando falten **60 minutos** para el inicio de una cita **pendiente**, crear una tarea para llamar al cliente y confirmarla.*

### 2.1 Ficha
| Campo | Valor |
|---|---|
| **Cuando** | **Tiempo relativo** a la **hora de inicio de la cita**: **[60]** minutos antes. **Excepción de horario:** si la cita es a la **hora de apertura** (no hay [60] min de margen desde que abre el taller), el aviso se crea **[60] min antes del cierre del día hábil anterior** (ej.: cierre 18:00 → 17:00). Los días hábiles salen del horario semanal de Configuración |
| **Y si** (de fábrica) | La cita está en estado **Pendiente**, tiene fecha y hora, y no está eliminada · todavía **no pasó** la hora de inicio |
| **Y si** (el usuario puede añadir) | Sede de la cita = … *(nuevo)* |
| **Entonces** | **Crear tarea** (ver 2.3) |
| **Clave anti-duplicado** | `confirm-{cita}`: **una tarea por cita** |
| **Se cierra cuando** | La cita se marca **Confirmada** desde la tarea (botón «✓ Confirmada»), o se cambia a Cancelada / No asistió |
| **Botones de la tarea** | «▣ Abrir cita» · «＄ Ver cotización» (si la cita tiene) · «✓ Confirmada» (si sigue Pendiente) |
| **Responsable / lista** | Editables (por defecto: cajera / Posventa) |

### 2.2 Pantalla (esquema)
```
Regla: Confirmar cita                                            [● Activa]
 CUANDO   [Tiempo relativo ▾]  [ 60 ] minutos antes de [inicio de la cita ▾]
          Si la cita es a la hora de apertura: 60 min antes del cierre del día hábil anterior
 Y SI     [cita en estado Pendiente]   [+ condición]
 ENTONCES [Crear tarea ▾]  Lista [Posventa ▾]  Responsable [Cajera ▾]
          Prioridad [Alta]  Vence [fecha de la cita, hasta la hora de la cita]
          Título   Confirmar cita {cita} · vehículo {placa}      [Probar] [Guardar]
```

### 2.3 Plantilla de la tarea
| Campo | Valor |
|---|---|
| Tipo / estado | Tarea · Pendiente |
| **Título** | `Confirmar cita {código de cita} · vehículo {placa}` (si no hay vehículo: «sin vehículo») |
| **Prioridad** | **Alta** |
| Inicio | hoy, hora actual |
| **Vence** | **la fecha de la cita**, con hora límite = **hora de la cita** |
| Etiquetas | `Automatización`, `Confirmar cita` |
| Vínculo | la propia cita (para abrirla desde la tarea) |
| **Detalle** | *Llamar a {cliente} para confirmar la cita del {fecha} a las {hora}{ si es a la apertura: «(es a la hora de apertura: el recordatorio se crea una hora antes del cierre del día hábil anterior)»}. Marcar la cita como Confirmada, Cancelada o No asistió.{ Cotización {código}. si existe}* |

### 2.4 Paso a paso
1. **Automatizaciones → + Nueva regla → Plantillas → «Confirmar cita»**.
2. **Cuando → Tiempo relativo → inicio de la cita → 60 minutos antes.**
3. **Y si:** dejar «cita Pendiente»; añadir sede si se quiere limitar.
4. **Entonces → Crear tarea:** lista, responsable, título y detalle.
5. **Probar** (lista las citas de hoy que ya entrarían en ventana) → **Guardar** → activar.

### 2.5 Pruebas de regresión
- Cita Pendiente a las 10:00 y hora actual 09:00 → **1** tarea «Confirmar cita…» con prioridad Alta, vence ese día a las 10:00.
- Cita Pendiente a las 10:00 y hora actual 08:30 → **0** tareas (aún no es la hora).
- Cita a la hora de apertura (08:00) → la tarea aparece desde las **17:00 del día hábil anterior**.
- Cita ya **Confirmada** → **0** tareas.
- Segunda pasada → **0** tareas nuevas.
- Marcar «✓ Confirmada» desde la tarea → cita Confirmada y tarea Completada.

## 3. Regla 3 — Posventa: llamada y encuesta
**En una frase:** *Cuando pasen **5 días hábiles** desde la salida de una ODS archivada (y hasta el día hábil 7), crear una tarea para llamar al cliente y enviarle la encuesta.*

### 3.1 Ficha
| Campo | Valor |
|---|---|
| **Cuando** | **Tiempo relativo** a la **fecha de salida de la ODS** (se guarda al archivarla): **[5]** días hábiles después. **Ventana:** si el sistema no estuvo abierto ese día, se crea **hasta el día hábil [7]**; pasado ese día ya no se crea |
| **Y si** (de fábrica) | La ODS está **Archivada**, tiene **fecha de salida** y no está eliminada |
| **Y si** (el usuario puede añadir) | Sede = … · **El cliente tiene celular** *(nuevo; hoy la regla no lo exige, aunque `docs/CONTEXTO_TESIS.md` dice que la posventa requiere celular utilizable: ver sección 5)* |
| **Entonces** | **Crear tarea** (ver 3.3) |
| **Clave anti-duplicado** | `post-{ODS}`: **una tarea por ODS** |
| **Se cierra cuando** | Se **registra la encuesta** de esa ODS (completa las tareas de posventa abiertas de esa ODS) |
| **Botones de la tarea** | «☺ Encuesta de satisfacción» · «▤ Abrir ODS» |
| **Responsable / lista** | Editables (por defecto: cajera / Posventa) |

### 3.2 Pantalla (esquema)
```
Regla: Posventa · llamada y encuesta                             [● Activa]
 CUANDO   [Tiempo relativo ▾]  [ 5 ] días hábiles después de [salida de la ODS ▾]
          Si no se abrió el sistema ese día: se crea hasta el día hábil [ 7 ]
 Y SI     [ODS archivada con fecha de salida]  [+ condición]
 ENTONCES [Crear tarea ▾]  Lista [Posventa ▾]  Responsable [Cajera ▾]
          Prioridad [Normal]  Vence [día hábil siguiente]
          Título   Posventa · llamar a {cliente} (ODS {ods}) y enviar encuesta   [Probar] [Guardar]
```

### 3.3 Plantilla de la tarea
| Campo | Valor |
|---|---|
| Tipo / estado | Tarea · Pendiente |
| **Título** | `Posventa · llamar a {cliente} (ODS {ods}) y enviar encuesta` (si no hay nombre: «cliente») |
| **Prioridad** | Normal |
| Inicio | hoy, hora actual |
| **Vence** | **el día hábil siguiente** a hoy |
| Etiquetas | `Automatización`, `Posventa` |
| Vínculo | la ODS |
| **Detalle** | *Han pasado {días hábiles} días hábiles desde la salida ({fecha_salida}). Llamar a {cliente} ({teléfono si existe}) para preguntar cómo va el servicio de {placa} y enviar la encuesta de satisfacción. Vence al día hábil siguiente.* |

### 3.4 Paso a paso
1. **Automatizaciones → + Nueva regla → Plantillas → «Posventa»**.
2. **Cuando → Tiempo relativo → salida de la ODS → 5 días hábiles después**; en la ventana, **7**.
3. **Y si:** dejar «ODS archivada con salida»; añadir **cliente con celular** y/o sede si se desea.
4. **Entonces → Crear tarea:** lista, responsable, título y detalle.
5. **Probar** (muestra qué ODS archivadas entrarían hoy) → **Guardar** → activar.

### 3.5 Pruebas de regresión
- ODS archivada con salida hace 5 días hábiles → **1** tarea de posventa que vence al día hábil siguiente.
- Salida hace 4 días hábiles → **0** tareas.
- Salida hace 7 días hábiles (sistema no abierto antes) → **1** tarea (dentro de la ventana).
- Salida hace 8 días hábiles → **0** tareas (fuera de la ventana).
- Segunda pasada → **0** tareas nuevas.
- Registrar la encuesta → la tarea queda **Completada**.
- Los días no hábiles no cuentan: el horario semanal de Configuración decide qué día es hábil (no se verificó que existan feriados como excepción).

## 4. Lo que comparten las tres
| Aspecto | Comportamiento actual (se conserva) |
|---|---|
| Responsable y lista de destino | Un valor por regla (hoy es **uno global**: pasa a ser **por regla**) |
| Aviso | Mensaje «Se ha creado 1 tarea nueva» / «Se han creado N tareas nuevas: revisa tu bandeja» y campana 🔔 para el responsable y el administrador |
| Historial | Cada tarea creada queda con fecha, hora simulada, regla, título y origen (automático o manual); máximo 300 |
| Cuándo corre | Mientras el sistema está abierto, de forma periódica (con al menos 20 s entre pasadas; la frecuencia exacta no se verificó) y al pulsar «▶ Ejecutar ahora» |
| Hora simulada | Si está activada, todas las reglas por tiempo usan esa hora |
| Etiqueta | `Automatización` (permite filtrar «mis tareas automáticas» y crear la vista personal) |
| Creada por | «Sistema» |
| Qué **no** hacen | **No agendan citas, no modifican ODS, citas, agenda ni dinero**. Solo crean tareas y avisos |

## 5. Diferencias y decisiones detectadas al transcribir
1. **Posventa sin exigir teléfono (INC-06 R1).** `docs/CONTEXTO_TESIS.md` dice que la posventa exige celular utilizable; la regla actual crea la tarea aunque el cliente no tenga teléfono (solo lo muestra si existe). Propuesta: añadir la condición «cliente con celular» **como opción** y decidir si va activada de fábrica. **Decisión tuya.**
2. **Vocabulario de estado de cita (OPEN-22).** La regla 2 filtra «Pendiente». Si se unifica el vocabulario (UML R8: RESERVADA/RECONFIRMADA…), la condición debe actualizarse.
3. **Estado «Cancelada».** Las reglas completan tareas con estado «Completada»; «Cancelada» queda para el sistema (OPEN-27).
4. **Una sola tarea abierta de km por vehículo y una por ciclo.** Se conserva; si el usuario prefiere avisar de nuevo tras N días sin respuesta, es una regla distinta *(nuevo)*.
5. **El cálculo de la regla 1 sigue en código** (línea temporal, tasa km/mes y reglas del plan). Del motor son los **parámetros, la plantilla de la tarea y la clave anti-duplicado**, no el cálculo. Además, **el cálculo de la tasa km/mes tiene dos versiones en conflicto** (OPEN-38): el motor usa la que decida esa decisión.
6. **Las tres reglas hoy se disparan por revisión periódica**, no por evento. Esto es correcto para tiempo y estado calculado, y es lo que reproduce la regresión.
7. **Los botones de la tarea están en el código** (`r6TaskPanel` ampliado por R7.4). En el motor nuevo viajarán con la plantilla para poder crear reglas con botones propios; en la Fase 1 basta con mantener los tres actuales.
